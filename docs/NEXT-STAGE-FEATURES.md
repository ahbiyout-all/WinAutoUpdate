# 다음 단계 기능 개선 설계

이 문서는 자아성찰 50회 감사(68건 수정) 이후의 기능 개선 설계와 적용 범위를 정의한다.
원칙은 다음과 같다.

- **실데이터만 표시**: 값이 없으면 `0`이나 추정값으로 채우지 않고 `없음`/`확인 불가`로 표시한다.
- **Fail closed**: 검증·기록·복구에 실패하면 조용히 계속하지 않고 중단하거나 명시적으로 표시한다.
- **시크릿 비노출**: 로그·리포트·명령줄·저장소에 토큰 원문을 남기지 않는다. 지문(해시)과 이벤트 메타만 기록한다.
- **기존 제약 유지**: 소프트 오버레이만 사용, WebView2 금지, 기능 업데이트 비활성, Server Core 오버레이 비활성, 순수 자작 C# DLL.

## 1. 토큰·보안 수명주기

### 현재 상태

- `AdminTokenStore`가 `%LOCALAPPDATA%\UpdateAgent\LabManager\runtime-admin-token.json`에 런타임 관리자 토큰을 저장한다.
- 저장은 임시 파일 + 원자적 이동 + ACL 제한으로 보호되고, 교체 즉시 인증에 반영된다.
- `/api/admin/token`이 상태를 반환하지만 **변경 시각·회전 필요 여부·감사 기록이 없다.**

### 설계

| 항목 | 내용 |
|---|---|
| 감사 로그 | `%LOCALAPPDATA%\UpdateAgent\LabManager\runtime-admin-token.audit.log`에 UTC 시각, 이벤트(`changed`, `rolled-back`, `loaded`, `rejected`) , 토큰 지문(SHA-256 앞 12자리)만 기록. 원문/개인정보는 기록하지 않는다. |
| 파일 보호 | 감사 로그도 토큰 파일과 동일하게 관리자/SYSTEM/현재 사용자 ACL로 제한하고, 크기 상한(256 KiB)을 넘으면 오래된 줄을 잘라낸다. |
| 회전 상태 | `AdminTokenStatus`에 `LastChangedAt`(UTC), `RotationDue`(기본 90일 경과), `AuditPathExists`를 추가한다. 기존 API 응답에 자동 포함된다. |
| 롤백 | 새 토큰 저장 실패 시 메모리에 보관한 이전 토큰으로 같은 원자적 경로를 다시 써서 복구하고 `rolled-back` 이벤트를 남긴다. 이전 토큰의 디스크 백업은 만들지 않는다. |
| 거부 기록 | placeholder·길이 부족·에이전트 토큰 충돌로 거부된 요청도 `rejected` 이벤트를 남기되 지문은 남기지 않는다. |

### 수용 기준

- 토큰 변경 직후 감사 로그에 `changed` 1건이 추가되고 상태에 `LastChangedAt`이 채워진다.
- 저장 중 오류가 나면 이전 토큰이 복구되고 `rolled-back`이 기록된다.
- 잘못된 토큰 요청은 토큰 원문 없이 `rejected`만 기록된다.
- 시계 주입으로 90일 경과를 재현하면 `RotationDue=true`가 된다.

## 2. 무인 배포·운영 자동화

### 현재 상태

- `scripts/deploy-agents.ps1`가 인벤토리 CSV로 PC별 패키지를 생성한다.
- 중복 이름·경로 이탈·placeholder 토큰·ACL은 이미 검증한다.
- **생성 전 연결 확인이 없고, 생성 결과를 검증하는 리포트가 없다.**

### 설계

| 항목 | 내용 |
|---|---|
| 사전 점검 | 패키지 생성 전에 LabManager URL의 `/api/health`를 HTTP로 확인한다. 실패하면 패키지를 하나도 만들지 않고 종료한다. `-SkipPreflight`로만 우회한다. |
| 토큰 검증 | 토큰 파일 첫 줄의 길이가 8자 이상인지, placeholder가 아닌지 생성 전에 확인한다(인스톨러와 동일한 규칙). |
| 배포 리포트 | `deploy\agents\deployment-report.json`에 생성 시각(UTC), 인스톨러 이름·버전·SHA-256, LabManager URL, PC 수, 각 PC별 토큰 파일 SHA-256을 기록한다. **토큰 원문은 기록하지 않는다.** |
| 검증 모드 | `-Verify`는 패키지를 재생성하지 않고 리포트의 해시와 실제 파일을 비교한다. 설치 파일/INI/토큰 파일이 바뀌면 0이 아닌 코드로 종료한다. |
| 언어 | 스크립트 도움말·메시지는 영어를 유지한다. |

### 수용 기준

- LabManager에 연결할 수 없으면 패키지 디렉터리와 리포트가 생성되지 않는다.
- 리포트와 실제 파일이 일치하면 `-Verify`가 성공하고, 설치 파일을 한 바이트 바꾸면 실패한다.
- 리포트를 텍스트로 검색해도 토큰 원문이 나오지 않는다.

## 3. 대시보드·실시간 모니터링

### 현재 상태

- `monitor.js`가 `/api/admin/live` 스트림을 `fetch`로 읽고 지수 백오프로 재연결한다.
- `LiveSnapshot`에 에이전트/작업 수와 활성 작업 수가 있지만 **오래된 상태(stale) 구분이 없다.**
- 값이 없는 필드는 `0`으로 표시되어 "데이터 없음"과 구분되지 않는다.

### 설계

| 항목 | 내용 |
|---|---|
| 스냅샷 | `LiveSnapshot`에 `StaleCount`(마지막 체크인이 기준 시간보다 오래된 PC 수)와 `SnapshotAt`을 추가한다. 기존 필드는 유지한다. |
| 표시 | 모니터 상단에 `최종 갱신` 시각과 재연결 횟수를 표시한다. 값이 없는 필드는 `없음`으로, 확인할 수 없는 플래그는 `확인 불가`로 표시한다. |
| 필터 | PC 이름/작업 ID 검색과 상태(전체/작업 중/확인 필요/오프라인) 선택을 함께 적용한다. |
| 연결 | 스트림이 정상 종료되어도 재연결하고, 성공 시 백오프를 초기화한다. 인증 실패는 재연결하지 않고 토큰 입력을 요청한다. |

### 수용 기준

- 체크인이 오래된 PC는 `StaleCount`에 포함되고 화면에 `오래됨`으로 표시된다.
- 값이 없는 항목이 `0`이 아닌 `없음`으로 표시된다.
- `node --check`와 스냅샷 회귀 테스트가 통과한다.

## 4. 오프라인·실패 복구

### 현재 상태

- `CommandExecutor`가 명령 결과를 디스크 큐에 보관하므로 오프라인 중 결과는 재전송된다.
- 체크인 실패는 경고 로그만 남기고 **고정 주기로 다시 시도**한다. 실패 횟수·마지막 실패 시각·백오프가 없다.

### 설계

| 항목 | 내용 |
|---|---|
| 재시도 정책 | 순수 C# `CheckInRetryPolicy`를 추가한다. `NextDelaySeconds(failures, baseSeconds, maxSeconds)`는 `base * 2^min(failures, 10)`을 상한까지로 계산하고, 성공 시 0으로 초기화한다. OS API 의존성 없음. |
| 실패 추적 | `LabManagerClient`에 `ConsecutiveFailures`, `LastFailureAt`을 추가한다. 성공 시 모두 초기화하고, 오류 메시지에 토큰/URL 자격증명이 들어가지 않도록 정제한다. |
| 워커 적용 | `Worker`가 고정 간격 대신 재시도 정책의 지연을 사용한다. 로컬 제어 요청은 기존처럼 즉시 체크인을 깨운다. |
| 오프라인 표시 | 다음 성공 체크인 시 이전 실패 횟수를 텔레메트리 `LastError`에 `오프라인 복구` 접두로 남겨 교사가 복구 시점을 알 수 있게 한다(값이 없으면 null 유지). |

### 수용 기준

- 실패가 누적되면 지연이 30초 → 60초 → 120초로 증가하고 상한을 넘지 않는다.
- 성공 직후 실패 횟수가 0이 되고 다음 지연이 기본값으로 돌아온다.
- 취소 토큰이 취소되면 지연 중 즉시 종료한다.

## 적용 순서

1. 영역별 구현(충돌 없는 파일 범위) 및 회귀 테스트 추가
2. 통합 `dotnet test`, PowerShell 파서, YAML/JS 구문 검사
3. `docs/WORKLOG.md`에 적용 결과 기록
4. 사용자 승인 후 버전 상향·태그·Release 게시

### 적용 결과 (2026-11-26)

4개 영역 모두 적용했고 통합 테스트 313개가 통과했습니다. 상세 내역은 `docs/WORKLOG.md`에 있습니다.
구현 과정에서 설계 대비 다음 차이가 있었습니다.

- 토큰 상태 필드 이름은 `AuditAvailable`로 했습니다(설계의 `AuditPathExists`보다 실제 쓰기 가능 여부를 반영).
- 감사 로그의 `loaded`는 유효한 override가 읽힌 경우에만 기록합니다(잘못된 파일은 기존 경고 후 무시).
- 배포 스크립트의 최소 토큰 길이는 C# 소스를 읽지 않고 `8`로 고정했습니다(C# `TokenGuard.MinimumLength`와 동일).
- 모니터의 상태 선택·연결 메타 요소는 `monitor.html` 수정 없이 `monitor.js`가 런타임에 삽입합니다.
- 대시보드는 `/api/admin/overview` 응답에 `staleCount`/`snapshotAt`이 있으면 우선 사용하고,
  없으면 `lastSeen`과 마지막 성공 갱신 시각으로 계산합니다(`Program.cs` 변경 없음).
- 체크인 지연 선택은 테스트 가능하도록 `Worker.ResolveCheckInDelaySeconds`로 분리했습니다.
- HTTP 성공 본문이 비어 있어도 재시도 상태는 초기화합니다(서버가 체크인을 받았으므로 백오프 불필요).

### 2차 감사 결과 (2026-11-26, v0.1.43 게시)

같은 6개 영역을 다시 감사해 고유 결함 37건을 수정했습니다.
중복 보고된 재부팅/세션 조회 실패는 하나의 tri-state 설계로 통합했습니다.
새 회귀 테스트는 `Audit50Round2*.cs` 3개 파일에 있으며, 정적 스크립트 검증도 포함합니다.
통합 테스트는 363개 통과, 0 실패, 0 건너뜀입니다.
상세 내역과 산출물 해시는 `docs/WORKLOG.md`의 2차 감사 항목을 참조하세요.
